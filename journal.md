# SwarmTrace — Development Journal

## Project Overview
SwarmTrace is a "pytest for AI agents" — an observability platform for LLM multi-agent swarms. Built for the AMD Hackathon, it provides tracing, debugging, token budgeting, tool attention (ISO scoring), web scraping traces, and regression detection. Two frontends: a TanStack Start dev-server and a Next.js 16 dashboard (frontend-next). Backend is Python/FastAPI with SQLite storage.

### 🔴 REMAINING / NEW PRODUCTION ISSUES

#### 1. Missing `routeTree.gen.ts` (BLOCKER for frontend/dev-server)
- **Severity**: 🔴 Build-breaking
- **File**: `frontend/dev-server/src/router.tsx` line 3
- **Problem**: `import { routeTree } from "./routeTree.gen"` — this file is generated by TanStack Router CLI at build time and does not exist in the repo. Running `vite build` will fail.
- **Fix**: Run `npx @tanstack/router-plugin` during build, or add a prebuild script. For production, the generated file should be committed or built in CI.

#### 2. Five identical `swarm_module_*.py` files
- **Severity**: 🟡 Code smell / maintenance burden
- **Files**: `swarm_module_0.py` through `swarm_module_4.py`
- **Problem**: All 5 files are identical (1069 bytes each), only class/file number differs. They run simulation at import time (side-effect pollution).
- **Fix**: Merge into a parameterized `SwarmTraceSimulator(index)` in a single file, move run loop under `if __name__ == "__main__"`.

#### 3. Duplicate `replay` implementation
- **Severity**: 🔵 Code duplication
- **Files**: `tracely/cli.py` (line 93–129) and `tracely/replay.py` (line 4–21)
- **Problem**: Two independent implementations of `replay()`. `cli.py` has rich+plain fallback, `replay.py` is plain only.
- **Fix**: Pick one location; have the other import from it.

#### 4. No `py.typed` marker
- **Severity**: 🔵 Type-checker compatibility
- **Problem**: Type checkers (mypy, pyright) will ignore the package.
- **Fix**: Add empty `tracely/py.typed` file.

#### 5. `setup.py` vs `README.md` Python version mismatch
- **Severity**: 🔵 Documentation inconsistency
- **setup.py**: `python_requires=">=3.8"`
- **README.md**: "Python 3.10+"
- **Fix**: Align both to the same minimum version.

#### 6. `frontend/dev-server/src/lib/api/traces.functions.ts` — hardcoded relative path
- **Severity**: 🟡 Fragile in production
- **Problem**: `path.join(process.cwd(), "../../swarm_trace_analysis.json")` breaks if the server is started from a different directory.
- **Fix**: Use environment variable `TRACE_ANALYSIS_FILE` with a sensible default.

#### 7. `use-api-live-traces.ts` — silent fallback to demo data
- **Severity**: 🟡 User confusion
- **Problem**: On fetch failure, the hook silently shows `DEMO_TRACES` with no indication to the user that data is fake.
- **Fix**: Expose an `error` state from the hook so UI can show a banner (already done in frontend-next, but not in dev-server).

#### 8. `tracely/regression.py` — hardcoded model string
- **Severity**: 🔵 Maintenance risk
- **Problem**: `model="anthropic/claude-haiku-4-5-20251001"` is hardcoded and will go stale.
- **Fix**: Make it configurable via `TRACELY_REGRESSION_MODEL` env var.

#### 9. `tracely/tool_attention.py` — silent fallback on missing dependencies
- **Severity**: 🟡 Silent wrong behavior
- **Problem**: If `sentence-transformers` or `faiss` aren't installed, `_index` is set to `None` and `select()` silently returns the first `k` tools with no indication.
- **Fix**: Raise `ImportError` with installation instructions, or at least `warnings.warn`.

#### 10. `.env` files committed to repo
- **Severity**: 🔵 Security hygiene
- **Files**: `frontend/dev-server/.env`, `frontend-next/.env.local`
- **Problem**: `.gitignore` excludes `.env` but these are already tracked. Contains `VITE_API_BASE_URL=http://localhost:8000`.
- **Fix**: `git rm --cached` the files and add `.env.example` templates.

#### 11. `trace_analyzer.py` — unused `import random`
- **Severity**: 🔵 Cosmetic
- **Problem**: `random` imported at top but only used in standalone `generate_sample_traces()` function.

#### 12. `swarm_metrics.py` — `generate_sample_metrics` swallows the collector
- **Severity**: 🟡 Design issue
- **Problem**: Function creates a `MetricsCollector` internally and never returns it. Caller can't call `end_session` or `export_session`.
- **Fix**: Return `(collector, metrics)` tuple, or make it a static method on `MetricsCollector`.

#### 13. Frontend dependency risks
- **Severity**: 🔵 Risk awareness
- **`frontend/dev-server`**: Uses `nitro: 3.0.260429-beta`, `vite: ^7.3.1` — both pre-release/unstable versions.
- **`frontend-next`**: Uses `next: 16.2.6`, `react: ^19` — cutting-edge, but stable releases.
- **Risk**: Beta dependencies may have breaking changes. Pin versions for production.
